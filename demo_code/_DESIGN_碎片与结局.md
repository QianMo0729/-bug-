# 总设计：碎片推理链 + 结局状态机

> 这份文档是"跨文件"的全局设计，单个 .py 的 docstring 只能讲自己那一关。
> 碎片链和结局分支横跨所有文件，必须在这里统一描述。

---

## 一、世界观与"代码即关卡"的基本约定（沿用 main.py）

- 上半屏 = 房间/像素地图，下半屏 = 当前文件的代码面板。
- 玩家的移动/拾取/粘贴会**反向改写代码面板**，代码行随进度高亮。
- `agent_bot.bot_say` = 机器人对话气泡；`agent_bot.system_prompt` = 中上方淡入淡出的系统提示。
- `time`（小时）和 `temp`（CPU 温度℃）**只随进度增加，不随真实时间增加**（idea.md 设定）。代码里每一处 `time += / temp +=` 都对应玩家界面状态栏的真实跳数。
- 进入一个区块才解锁该文件的代码浏览权限（标签栏点亮）。
- `ctrl/cmd + 单击` 方法名/类名 = 跳转到定义（即切换到对应 .py 文件这一关）。

## 二、文件 → 关卡 → 教学点 总览

| 顺序 | 文件 | 关卡主题 | 教 Python 什么 | 异常现象（推理链线索） | 碎片 |
|---|---|---|---|---|---|
| 1 | `main.py` | 出生/分岔 | 变量、if/elif、while、break/continue、list 下标、移动序列 | 开场 `import bug_maker`：正常程序为何要导入"造bug"模块？ | 碎片①（藏在左侧"无意义"房间，奖励好奇心） |
| 2 | `maybe_bug.py` | 类与对象 / 4 个方法小房间 | 类、嵌套循环、遍历时改列表、字典 KeyError、递归基线 | `bug_maker.unresponed_bug()`：程序居然**主动**制造无响应 bug | 碎片②（buggers 群后方） |
| 3 | `function.py` | 函数小镇 | 形参/返回值、作用域、可变默认参数坑 | 一个函数被人**事后篡改**过，留有 `# patched by ?????` | 碎片③（被篡改函数体内） |
| 4 | `runtime_guard.py` | 运行时守卫 / 结局闸口 | try/except、裸 except 吞异常、None 判断 | 异常处理器在**故意隐藏**某个作者的报错（销毁证据） | 碎片④（被吞掉的 except 块里，含 AUTHOR 值） |
| 5 | `bug_maker.py` | 隐藏副本 / 真结局 | `is` vs `==`、签名比对、收束全部知识点 | 真相：所有 bug 同一作者签名 = 老板 | —（这里**使用**碎片） |

## 三、碎片推理链（重点：思维链条必须自洽）

碎片不是收藏品，**4 片拼起来 = 一个被拆散的溯源函数 `_trace(sig)`**。它平时被 `bug_maker.py` 以"碎片化/被注释"的形式藏起来，玩家把它复原才能运行。

```python
# 4 片碎片复原后的样子（玩家在 bug_maker.py 关卡里把它们粘回去）
AUTHOR = "B055"            # 碎片④给出的值（看着像乱码，其实是 BOSS 的 leetspeak）

def _trace(sig):           # 碎片①：函数头
    found = []             # 碎片②：收集容器
    for bug in ALL_BUGS:   # 碎片②：遍历所有已记录的 bug
        if bug.author is sig:   # 碎片③：比对作者  ← 这里藏着玩家要修的 bug（is 应为 ==）
            found.append(bug)
    return found           # 碎片③：返回命中列表
```

### 链条的逻辑闭合点（为什么玩家会一步步信服）
1. **动机异常**（main.py）：正常程序不会 `import bug_maker`。先种下"不对劲"。
2. **行为异常**（maybe_bug.py）：程序不只是有 bug，而是**主动调用** `unresponed_bug()` 去造 bug。从"有bug"升级到"有人在造bug"。
3. **人为痕迹**（function.py）：发现一个本来正常的函数被事后 patch，且作者栏被涂成 `?????`。从"有人造"升级到"有具体某个人"。
4. **掩盖证据**（runtime_guard.py）：异常处理器专门吞掉某作者签名的报错——说明那个人**知道自己在干坏事并刻意隐藏**。这一关的碎片④正好泄露了被吞签名的值 `AUTHOR = "B055"`。
5. **实锤**（bug_maker.py）：把 `_trace` 复原 + 修好它自身的 `is/==` bug（呼应"代码自己也会有bug"的主题），传入 `AUTHOR` 运行，命中**全部** bug → 全是同一只手。此人 = 老板。证据链闭合，开战。

> 设计要点：每一步都比上一步"更具体"（不对劲→有人造→具体某人→此人在掩盖→此人是谁），是单调收敛的推理，不会出现跳跃或巧合。即便玩家没集齐前面的常规结局，只要走完这条链就能进真结局（符合 idea.md "前面结局没完成也能完成隐藏结局"）。

### 碎片的"物理"形态与放置
- 碎片在地图上是**漂浮的、带代码字样的青色光块**，拾取时代码面板对应位置闪现该行。
- 故意放在**反直觉/反奖励的位置**，鼓励探索而非通关：
  - 碎片①：left 那个"无意义房间"——惩罚式房间里反而有奖励。
  - 碎片②：buggers 群移动路径的死角，要先把 `buggers_count` 调到 9（变 3×3 静止阵）才安全走过去拿。把"调参"变成解谜手段。
  - 碎片③：篡改函数的函数体内部，必须先看懂可变默认参数 bug 才会去翻那一行。
  - 碎片④：被裸 except 吞掉的那个分支里，要先把 `except: pass` 改成打印异常，证据才显形。
- 凑齐 4 片后，main.py 标签栏旁边浮现一个**之前一直灰着的 `bug_maker.py` 标签**亮起，可点入隐藏副本。

## 四、结局状态机（与碎片链并行的两个全局变量：time / temp）

结局判定集中在 `runtime_guard.py` 的 `finalize()`，输入是 `time / temp / fragments / bug_fixed`。

```
                      ┌─ temp 触顶(=100) ───────────────► [崩溃] CPU过热Boss，没挡住 → 烧坏崩溃
                      │
进入 runtime_guard ───┤─ time > 3.0h ──► 睡意Boss(接咖啡/躲zzz, 睡意条20s基线)
                      │                    ├─ 撑满40s 且 之后修好bug ─► [不眠之夜]
                      │                    └─ 没撑过40s ──────────────► [倒头就睡]
                      │
                      ├─ fragments == 4 ──► 解锁 [隐藏副本] → 老板Boss → [真·结局]
                      │
                      └─ 仅修好表面bug(无碎片/未触发上面) ─► [加班] 红色报错弹窗淹没屏幕
```

- **temp**：每关进度累加（见各文件 `temp +=`）。设阈值 100℃ 触发崩溃 Boss。崩溃 Boss 是"按节奏点击散热"小游戏（区别于睡意 Boss 的接咖啡）。
- **time**：每关进度累加。>3.0h 进睡意 Boss。睡意条默认 20s 涨满，喝咖啡 -、撞 zzz +，撑 40s 通过。
- **加班** 是"什么都没多做"的默认坏结局：表面 bug 修了，但因为没顺着碎片链查，真凶还在，红色报错重新淹没屏幕（呼应开场老板那句"修不完别下班"）。
- **真·结局** 才是唯一"治本"的结局：揪出老板。其余都是"治标/失败"。
- 隐藏结局在**通关任意一个普通结局后**才在结局列表里显示"未解锁"占位（idea.md），但不强制前置。

## 五、Boss 战一览（玩法差异化，避免重复）

| Boss | 触发 | 玩法 | 失败/成功 |
|---|---|---|---|
| 睡意 | time>3h | 横版接咖啡 ☕ / 躲 `zzz` 弹幕，管理睡意条 | 撑 40s 成功 / 否则倒头就睡 |
| CPU过热 | temp=100 | 节奏点击"散热片"压温度，温度涨太快点不过来则烧坏 | 压回安全区成功 / 否则崩溃 |
| 老板（真Boss） | 集齐碎片 | 综合关：用前面学到的 break/continue/字典/异常去"反注入"，把老板源源不断生成的 bug 弹幕拆解 | 清空 bug 队列获胜 |

## 六、给实现的提示（不绑定任何现有 index）

- 每关 .py 文件 = 一个场景；`game_setup.set_scene(name)` 切场景。
- 碎片系统只需一个全局 `fragments: set()`，拾取即 `fragments.add(n)`。
- 结局判定是纯函数 `finalize(time, temp, fragments, bug_fixed) -> ending_name`，便于单测。
- 所有 `bot_say / system_prompt` 文案已写进各 .py，直接当本地化字符串用，禁外部请求（符合硬性约束）。
